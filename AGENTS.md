# TUI Kanban Agent Guide

This repository contains a live OpenTUI React canvas that an agent can edit while `bun run dev` remains running.

## File ownership

- `src/board.tsx` is the live canvas. Edit this file to change the terminal UI.
- `src/index.tsx` is the stable host responsible for rendering, watching files, hot loading, and error recovery. Do not edit it for ordinary UI or content changes.
- `src/.hot/` contains temporary versioned modules generated by the host. Never edit or depend on it.

## How to update the live UI

1. Read the current `src/board.tsx` before editing so that user changes are preserved.
2. Modify `src/board.tsx` directly using OpenTUI React JSX.
3. Keep a default-exported React component:

   ```tsx
   export default function Board() {
     return (
       <box width="100%" height="100%" flexDirection="column">
         <text>Hello from the agent</text>
       </box>
     );
   }
   ```

4. Save the file. The running host detects the change and swaps in the new module without restarting the process or renderer.
5. Run `bun run typecheck` after editing.

Do not run, restart, or kill `bun run dev` merely to apply a `board.tsx` change. The user may already have the TUI open.

## OpenTUI API

Write native OpenTUI React components directly. No project-specific wrapper API is required.

- JSX elements such as `<box>`, `<text>`, `<input>`, `<select>`, and `<scrollbox>` come from `@opentui/react`.
- Hooks such as `useKeyboard`, `useRenderer`, and `useTerminalDimensions` may be imported from `@opentui/react`.
- Core types and utilities may be imported from `@opentui/core`.
- React state and effects may be imported from `react`.
- Use public package entry points only; never deep-import package internals.

Example interaction:

```tsx
import { useKeyboard } from "@opentui/react";
import { useState } from "react";

export default function Board() {
  const [selected, setSelected] = useState(0);

  useKeyboard((key) => {
    if (key.name === "up") setSelected((value) => Math.max(0, value - 1));
    if (key.name === "down") setSelected((value) => value + 1);
  });

  return <text>Selected: {selected}</text>;
}
```

## Terminal layout rules

- Design for terminal cells, not browser pixels.
- Prefer compact, information-dense layouts.
- Do not add gaps between adjacent panels or unnecessary margins and padding.
- Use Flexbox properties supported by OpenTUI, including `flexDirection`, `flexGrow`, `flexBasis`, `minWidth`, and `minHeight`.
- Give adjacent equal-width columns `flexGrow={1}`, `flexBasis={0}`, and `minWidth={0}`.
- Use `minHeight={0}` on growing containers when children need to fit or scroll.
- Keep essential controls and status information visible on small terminals.
- Ensure every mapped child has a stable `key`.

## Hot-load behavior

- A valid save replaces the displayed component in the existing process.
- Component-local React state may reset after a module replacement.
- A compile or import error leaves the last valid component visible and shows the error in the host status line.
- Fix the source and save again; do not restart the host.
- Dynamically loaded code runs inside the host process with the user's permissions. Only add trusted code and dependencies.

## Validation

After modifying `src/board.tsx`, run:

```bash
bun run typecheck
```

Do not use `bun run --watch`, start a second TUI, or perform broad unrelated edits unless the user explicitly asks.
